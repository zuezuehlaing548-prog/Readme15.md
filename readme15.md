 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

1. 실행 환경과 방법

- 파일: `test15.c`
- 컴파일: `gcc -o test15 test15.c`
- 실행: `./test15`
- 환경: MacBook Air (macOS), 랜덤 seed = 12345
- 데이터: 0 ~ 999999 사이 랜덤 정수 (중복 가능). 과제 14와 같은 난수 함수를 사용했습니다.
- 데이터 크기 n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 삽입·삭제 횟수: n의 20% (200 / 400 / 800 / 1,600 / 3,200 / 4,000번)
- 두 방법은 같은 원본 데이터를 사용했습니다.

퀵 정렬 + 배열
- 과제 14에서 만든 퀵 정렬을 그대로 사용했습니다. 분할은 Lomuto 방식이고, **피벗은 Median-of-Three**입니다. (처음, 가운데, 끝 값의 중앙값)
- 삽입: 선형 탐색으로 위치를 찾고, 뒤의 데이터를 한 칸씩 뒤로 이동합니다.
- 삭제: 선형 탐색으로 값을 찾고, 뒤의 데이터를 한 칸씩 앞으로 이동합니다.

 AVL 트리 정렬
- 원본 데이터를 AVL 트리에 하나씩 삽입합니다. 그리고 중위 순회로 오름차순 결과를 만듭니다.
- 중복된 값은 노드의 `count`에 저장했습니다. 삭제할 때는 `count`를 1 줄이고, 1개만 있으면 노드를 삭제합니다.
- 균형이 깨지면 회전(LL, RR, LR, RL)으로 복구했습니다.
- 삽입·삭제는 트리에서 직접 했습니다.

 삽입·삭제 규칙
- 난수를 만들어서 짝수이면 삽입, 홀수이면 삭제를 선택했습니다.
- 삽입·삭제할 값은 새로운 난수로 따로 만들었습니다.
- 삭제할 값이 없으면 삭제하지 않고 다음 연산으로 갔습니다.
- 연산 순서와 값을 미리 만들어서 두 방법에 똑같이 사용했습니다.
- 실험이 끝난 후에 배열과 AVL 트리의 데이터가 같은지 확인했습니다. 모든 n에서 같았습니다. (`Verification` 출력)

 2. 측정 방법

**총 수행시간**
- `clock()`으로 측정했고, 단위는 ms입니다.
- 정렬 시작부터 마지막 삽입·삭제가 끝날 때까지 측정했습니다.
- 난수 생성, 원본 데이터 복사, 출력 시간은 제외했습니다.
- AVL은 트리 만들기, 중위 순회, 삽입·삭제 시간을 모두 포함했습니다.

**비교 횟수**
- 데이터 값끼리 비교할 때마다 `less()` 함수로 1씩 증가했습니다.
- 퀵 정렬의 피벗 선택 비교, 삽입 위치 탐색, 삭제 대상 탐색의 비교를 모두 포함했습니다.
- AVL에서는 노드 하나에서 "작은지", "큰지"를 각각 비교하면 2번으로 셌습니다. 같으면 2번 모두 실행한 것입니다.
- 균형 인수 비교와 반복문 인덱스 검사는 세지 않았습니다.

**데이터 이동 횟수**
- 데이터 값을 복사하거나 대입할 때마다 셌습니다.
- swap 1번은 3번으로 셌습니다.
- 배열에서 한 칸씩 이동하는 것은 1번씩 셌습니다.
- AVL에서는 새 노드에 값을 저장하는 것, 중위 순회 결과를 배열에 저장하는 것, 자식이 2개인 노드를 삭제할 때 값을 복사하는 것을 셌습니다.
- AVL의 포인터 연결 변경과 `height`, `count` 갱신은 세지 않았습니다.

**메모리 사용량**
- `malloc`으로 잡은 공간의 최대 사용량입니다. (자료구조 + 보조 공간)
- 퀵 정렬: 배열 `(n + 연산 횟수) x 4 Byte`. 삽입할 자리를 미리 잡았습니다.
- AVL: `노드 개수 x 32 Byte` + 중위 순회 결과 배열 `n x 4 Byte`. 노드 하나(`sizeof(Node)`)는 32 Byte입니다.
- 원본 데이터와 연산 목록은 두 방법이 같이 쓰는 입력이라서 제외했습니다.
- 재귀 호출 스택은 포함하지 않았습니다.

4. 비교·분석

4.1 총 수행시간과 비교 횟수 차이

모든 n에서 AVL 트리가 비교 횟수가 더 적었습니다. n=20,000에서 퀵 정렬은 42,804,161번이고 AVL은 481,097번입니다. 약 89배 차이입니다.
수행시간도 n이 커질수록 차이가 커졌습니다. n=1,000에서는 0.320 ms와 0.203 ms로 약 1.6배였습니다. n=20,000에서는 94.585 ms와 7.686 ms로 약 12.3배였습니다.

이유는 정렬 후의 삽입·삭제 방법이 다르기 때문입니다.
- 정렬 자체는 퀵 정렬도 O(n log n)이고, AVL 트리를 만드는 것도 n번 삽입 x O(log n)이라서 비슷합니다.
- 하지만 정렬된 배열에서는 삽입 위치와 삭제 대상을 선형 탐색으로 찾습니다. 한 번에 평균 n/2개 정도를 봅니다. 이것은 O(n)입니다.
- n=20,000일 때 연산이 4,000번이고, 배열 크기는 약 21,000입니다. 그래서 대략 4,000 x 10,000 = 4천만 번입니다. 실제 결과 42,804,161번과 비슷합니다.
- 삭제할 값이 없어서 건너뛴 연산(2,011번)도 배열은 탐색을 해야 해서 비교 횟수에 포함됩니다.
- AVL은 트리 높이만큼만 내려갑니다. 이것은 O(log n)입니다.
즉 퀵 정렬 쪽 비교 횟수의 대부분은 정렬이 아니라 **삽입·삭제의 선형 탐색**에서 나왔다고 생각합니다.
AVL은 노드 하나에서 비교를 2번까지 세는 기준을 사용했습니다. 그래도 AVL이 훨씬 적었습니다.

 4.2 삽입·삭제 과정의 데이터 이동 횟수 차이

n=20,000에서 퀵 정렬은 21,050,860번이고 AVL은 41,702번입니다. 약 505배 차이입니다. 비교 횟수보다 차이가 더 큽니다.
- 배열은 삽입할 때마다 뒤의 데이터를 모두 한 칸씩 뒤로 옮겨야 합니다. 한 번에 평균 n/2개 정도입니다. 삽입이 1,945번이어서 1,945 x 약 10,000 = 약 2천만 번입니다. 실제 결과와 비슷합니다.
- AVL은 데이터를 옮기지 않고 포인터만 바꿉니다. 포인터 변경은 이동 횟수에 넣지 않았습니다.
- AVL의 이동 횟수는 새 노드에 값을 저장하는 것(약 2만 번)과 중위 순회 결과를 저장하는 것(n = 20,000번)이 대부분입니다. 그래서 4만 번 정도로 적습니다.
그리고 AVL의 이동 횟수는 n이 2배가 되면 정확히 약 2배가 되었습니다. (2,099 → 4,197 → 8,406 → 16,778 → 33,467) 삽입·삭제 때문에 데이터가 이동하는 일이 거의 없다는 뜻입니다.

4.3 배열과 AVL 트리의 메모리 사용량 차이
메모리는 **AVL 트리가 더 많이 사용했습니다.** n=20,000에서 퀵 정렬은 96,000 Byte이고 AVL은 713,248 Byte입니다. 약 7.4배입니다. 모든 n에서 7.4~7.5배로 비슷했습니다.
- 배열은 데이터(int, 4 Byte)만 저장합니다. 96,000 Byte는 `(20,000 + 4,000) x 4`입니다.
- AVL은 노드 하나가 32 Byte입니다. 데이터 4 Byte 말고도 `count`, `height`, 왼쪽·오른쪽 포인터(8 Byte x 2)가 필요하기 때문입니다.
- 노드 약 2만 개이므로 약 63만 Byte이고, 중위 순회 결과 배열 80,000 Byte가 더해집니다.
- 중복된 값은 `count`로 합칠 수 있지만, 이번 실험에서는 중복이 거의 없어서 효과가 작았습니다.
배열은 삽입을 위해 4,000자리를 미리 잡았지만, 실제로 사용한 것은 삽입 1,945번뿐입니다. 그래도 배열의 메모리가 훨씬 적었습니다.

4.4 데이터 크기 증가에 따른 성능 변화

n이 2배가 될 때 증가 배수는 다음과 같았습니다.

| 구간 | Quick 비교 | AVL 비교 | Quick 이동 | AVL 이동 |
|---|---:|---:|---:|---:|
| 1,000 → 2,000 | 3.6배 | 2.2배 | 3.8배 | 2.0배 |
| 2,000 → 4,000 | 4.0배 | 2.2배 | 3.9배 | 2.0배 |
| 4,000 → 8,000 | 4.0배 | 2.2배 | 3.6배 | 2.0배 |
| 8,000 → 16,000 | 3.9배 | 2.2배 | 3.9배 | 2.0배 |

- **퀵 정렬 + 배열**은 n이 2배가 되면 비교 횟수와 이동 횟수가 약 4배가 되었습니다. 연산 횟수가 n에 비례해서 늘어나고, 연산 한 번의 비용(탐색, 이동)도 n에 비례해서 늘어나기 때문입니다. 그래서 O(n²)에 가까운 모양입니다.
- **AVL 트리**는 n이 2배가 되면 비교 횟수가 약 2.2배, 이동 횟수가 약 2배가 되었습니다. 연산 수는 n에 비례하고 연산 한 번은 O(log n)이라서 O(n log n)에 가깝습니다.
- 수행시간도 같았습니다. 퀵 정렬은 n이 2배가 되면 약 3.4~3.9배, AVL은 약 2~2.5배가 되었습니다.
- 그래서 n이 클수록 두 방법의 차이는 더 커졌습니다. 수행시간 차이는 1.6배(n=1,000)에서 12.3배(n=20,000)가 되었고, 비교 횟수 차이는 7.3배에서 89배가 되었습니다.
- 메모리는 두 방법 모두 n에 비례해서 늘어났고, 두 방법의 비율은 거의 일정했습니다.

 4.5 삽입·삭제가 반복되는 환경에서 유리한 자료구조

**AVL 트리**가 더 유리하다고 생각합니다.

- 정렬된 배열은 삽입·삭제마다 탐색과 이동이 O(n)입니다. AVL은 O(log n)입니다.
- 이번 실험의 n=20,000에서 AVL은 수행시간이 약 12배 빨랐고, 비교 횟수는 약 89배, 이동 횟수는 약 505배 적었습니다.
- AVL은 회전으로 균형을 유지해서 최악의 경우에도 높이가 O(log n)입니다. 그래서 데이터가 많아져도 성능이 안정적입니다.
하지만 단점도 있습니다.
- 메모리를 약 7.4배 더 사용합니다. (포인터와 부가 정보 때문)
- 회전 등 구현이 더 복잡합니다.
- 삽입·삭제가 거의 없고 한 번 정렬하고 끝나는 경우에는 배열이 더 단순하고 메모리도 적게 사용합니다.

5. 참고할 점 (실험의 한계)

- **삭제가 대부분 건너뛰어졌습니다.** 난수 범위가 0 ~ 999999로 넓어서, 삭제할 값이 데이터에 있는 경우가 적었습니다. n=20,000에서 삭제 성공은 44번이고 건너뜀은 2,011번이었습니다. 그래서 이번 실험은 실제로는 **삽입 위주**였습니다. 삭제가 많이 성공했다면 배열의 이동 횟수는 더 늘어났을 것이라고 생각합니다. (삭제도 뒤의 데이터를 앞으로 이동해야 하기 때문)
- 수행시간은 한 번만 측정했고 `clock()`을 사용했습니다. n=1,000처럼 시간이 아주 짧을 때(0.2~0.3 ms)는 측정 오차가 클 수 있어서, 1.6배 차이는 크게 의미가 없다고 생각합니다. 비교 횟수와 이동 횟수는 같은 seed로 항상 같은 값이 나와서 더 믿을 수 있습니다.
- 메모리에 재귀 호출 스택은 포함하지 않았습니다.
- 퀵 정렬의 피벗은 Median-of-Three 한 가지만 사용했습니다.
6. 결론

- 정렬만 하면 퀵 정렬과 AVL 트리 정렬은 둘 다 O(n log n)이라서 큰 차이가 없습니다.
- 정렬 후에 삽입·삭제를 반복하면 배열은 선형 탐색과 데이터 이동 때문에 연산마다 O(n)이 필요해서 크게 느려집니다. AVL은 O(log n)이고 데이터를 옮기지 않아서 훨씬 빠릅니다.
- n=20,000에서 AVL은 수행시간이 약 12배 빠르고, 비교 횟수는 약 89배, 이동 횟수는 약 505배 적었습니다. n이 클수록 차이는 더 커졌습니다.
- 대신 AVL은 메모리를 약 7.4배 더 사용했습니다.
- 따라서 삽입·삭제가 반복되는 환경에서는 메모리를 더 사용하더라도 AVL 트리가 더 좋은 선택이라고 생각합니다.
